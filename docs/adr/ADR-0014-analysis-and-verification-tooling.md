# ADR-0014: Analysis and Verification Tooling (scem_quicklook & scem_compare)

## Status
Accepted

## Context
Upstream specifications (FULL_IMPLEMENTATION.md §§2.2, 5.2, 12, 17) demand ergonomic, lightweight tools for rapid engineering inspection and regression verification of electromagnetic scattering databases (.h5 and .scemdb/.scem) generated by StrikeCEM.
Specifically:
1. Aerospace engineers need fast command-line inspection of database contents (frequencies, polarizations, sample counts, dynamic range, peak directions) without launching heavy GUI post-processors.
2. 1D angle cuts (azimuth cuts at constant elevation, or elevation cuts at constant azimuth) must be extractable with configurable angular resolution and rendered directly in terminals as ASCII sparklines/bars or machine-readable JSON.
3. Automated regression and solver cross-comparison require a dedicated comparison tool (`scem_compare`) evaluating point-by-point differences between baseline and candidate databases with user-defined dBsm tolerances, Mean Absolute Error (MAE), Root Mean Square Error (RMSE), complex scattering correlation, and peak RCS delta.

## Decision
1. Implement a unified analysis library under `strikecem::analysis`:
   - `DatabaseSummary summarize_database(const RcsQueryEngine& engine)`: extracts comprehensive statistics across all directions, frequencies, and channels.
   - `DatabaseCut extract_cut(...)`: extracts 1D azimuth or elevation sweeps with query interpolation.
   - `std::string render_ascii_cut(...)`: formats terminal-friendly horizontal bar charts showing RCS dynamic range.
   - `ComparisonMetrics compare_databases(engine_a, engine_b, tolerance)`: computes MAE, RMSE, complex scattering correlation $\rho = \frac{|\sum S_a S_b^*|}{\sqrt{\sum |S_a|^2 \sum |S_b|^2}}$, and peak delta.
2. Expose two standalone CLI utilities:
   - `scem_quicklook`: quick database statistical summary, 1D cut extraction, terminal ASCII visualization, and JSON output.
   - `scem_compare`: database difference evaluation, tolerance pass/fail thresholding, and JSON test report generation.
3. Integrate both tools into the top-level CMake build and install targets alongside `strikecem`.

## Consequences
- Fast, automated CI/CD database validation and regression gatekeeping without external Python dependencies.
- Clear, visual ASCII feedback in terminal sessions and logs.
- Strict complex-phase and amplitude comparison ensuring simulation integrity across revisions and platform architectures.
